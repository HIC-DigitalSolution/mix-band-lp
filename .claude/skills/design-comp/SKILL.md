# デザインカンプを起こす

**手順の正典は `harness/scenarios/design-comp.yaml` です。**ここはその Claude Code 側の
入口で、道具の割り当てだけを持ちます。**手順そのものをここに書き写さないでください。**
Codex は `.claude/` を読みません。二重に持つと、片方だけ古くなって誰にも分からなくなります。

読む順番:

1. `AGENTS.md` — 確定している事実と、却下済みの案。**推測で足せない項目**がここにあります
2. `harness/scenarios/design-comp.yaml` — カンプを起こす順番
3. `design/README.md` — 現在の検討物、採用済み・未確定・却下済みの区別
4. `docs/design-docs/pre-code-design-blueprint.md` — いま組み立てている設計と、実装前の判断
5. `docs/design-docs/information-request-checklist.md` — コピーと各セクションを埋めるための確認事項
6. `docs/design-docs/reference-sites.md` — 参考サイトから実測して取った構成・CSS・素材の事実
7. `docs/design-docs/lp-cvr-knowledge.md` — 何をどの順で言うか
8. `docs/design-docs/lp-visual-knowledge.md` — 画づくりの判断基準（§番号で引く）

`pre-code-design-blueprint.md` がまだ無い場合だけ、その項目を飛ばします。画像・カンプ・
支給バナーについて質問された場合は、ファイル名や説明文だけで判断せず、対象画像そのものを
開いて比較します。参考URLについてはスクリーンショットだけでなく、
`reference-sites.md` に残っているDOM・CSS・SVG素材の確認結果も使います。

## 現在の段階を守る

- 依頼者がデザインを検討している間は、HTML・Sass・JSの実装へ進みません。
- 配色見本や比較案は、依頼者が採用すると明言するまで「未確定」です。比較案をそのまま
  本番仕様へ昇格させません。
- カンプ内の仮表現と、実装時の仕上げを区別します。たとえば外周の粗い筆跡が
  配置確認用なら、最終形の輪郭まで粗いと決めつけません。
- 実装方法の相談には設計として答えてよいですが、依頼者が実装開始を指示するまでは
  コードを書きません。

そのうえで `node scripts/harness/harness-check.mjs` を走らせ、`[manual]` の行を全部読みます。
`lp-design.yaml` の前提が未決のままカンプを起こすと、**あとから構成ごとやり直しになります。**

## 道具（Claude Code 固有。ここだけがこのファイルの中身）

- カンプは **`design` スキル**でキャンバスに起こします。アートボードは `design/` に
  `.dc.html` で置き、1枚のキャンバスに並べて Artifact として公開します
- 既存カンプのレビューでは、支給素材と同じ観点で色面積・明暗・彩度・視線の強さを比較し、
  「感覚的に合わない」を測れる差へ翻訳します。数値は判断を補助する根拠で、依頼者の違和感を
  打ち消すためには使いません
- 寸法・コントラスト・容量を**測る**なら、ペインではなくヘッドレスの実機 Chrome。
  ペインは遅延画像の読み込み中に描画が追いつかず、スクロール中のコマが白く写ります。
  **見るのはペインでよく、測るのはヘッドレスで**
- 静的サーバは `.claude/launch.json` の `mix-lp`。`file://` は本番と挙動が違います
- カンプで決まったことは `docs/design-docs/<slug>.md` に。作るのは
  `node scripts/harness/new-plan.mjs design-doc <slug> --title "..."`

**カンプは成果物ではありません。**成果物は「決定」で、置き場は `docs/design-docs/` です。
キャンバスだけが残って決定が残らないと、次に触る人は画から意図を逆算するしかありません。

作業を終える前に `node scripts/harness/harness-check.mjs` を走らせます。`[manual]` は失敗では
ありませんが、確認済みにもせず、今回の判断に関係する項目を自分の目で照合します。
