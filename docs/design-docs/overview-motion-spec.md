# イベント概要セクションのスライド設計

- **作成日:** 2026-09-08
- **状態:** **2026-09-08 実装済み。**ただし**適用先が変わった** —— 下記「適用先の変更」を先に読むこと
- **参考:** [FUTURE TRAIN](https://www.futuretrain.jp/ja) の Visitor Guide / Future Imagination Course
- **対象:** MIX交流上等バンドLPの「イベント概要」

このメモはHTML・Sass・JavaScriptの実装ではない。後でコードを書くときに、参考サイトから借りる構造と、MIXへ置き換える内容を同じ判断で再現できるようにするための仕様である。

## 参考サイトから借りる構造

FUTURE TRAINのVisitor Guideは、最初に「どのように楽しみますか？」と問い、複数の選択肢を並べる。選択肢ごとに、画像、タイトル、補足タイトル、説明、条件、予約導線を持つ詳細パネルが同じ構造で続く。Future Imagination Courseはその先頭カードとして、没入体験の説明と画像、予約導線をまとめている。ページ上の情報がカード単位でまとまり、次のカードへ進んでも読者が同じ位置関係で内容を追える点を採用する。

借りるのは、**選択肢のレール → 同じ枠の詳細パネル → 次のカードへ進む流れ**だけである。FUTURE TRAINの文章、ロゴ、画像、色、固有の演出は使わない。

## 適用先の変更（2026-09-08）

**このスライド文法は「イベント概要（01 WHAT IS MIX → 02 CHIME → 03 CROSS）」には使わなかった。**
依頼者の判断で、**「YOUR NIGHT / いつもの夜を予定外に」の3項目**に適用した。

| | 実装したもの |
| --- | --- |
| 01 | いつもと違う刺激 —— 普段の来店とは違う高揚感を楽しむ |
| 02 | 関係が動くきっかけ —— 気持ちが揺れ動く瞬間に出会う |
| 03 | 非日常を体験 —— 恋愛リアリティショーの中へ入る |

**理由:** 確定事実（恋愛リアリティ体験・チャイム・最大4〜6組）は、
すでに独立したセクションとして順に読ませる構成が確定している。
スライドにすると同じ話を二度することになる。
一方 YOUR NIGHT の3項目は**並列で同格**なので、1枚ずつ送る形と噛み合う。

**下の「MIXへの翻訳」の表は当初案。採らなかった。**動きの仕様（次の端を見せる・
自動再生しない・reduced-motion）はそのまま使っている。

### 実装（2026-09-08 に横スライドから作り替え）

**依頼者の指定で、横スライドをやめて「スクロールで重なりながら現れる」形にした。**
参考は同じ futuretrain.jp の Future Imagination Course。**実物を開いて実装を読んで取った。**

| | 参考サイトの作り |
| --- | --- |
| 構造 | セクション内にビューポート高さ（`100svh`）の article を縦に並べる |
| 1枚目 | `position: sticky; top: 0` —— 上に貼り付く |
| 2枚目以降 | `position: relative` + `clip-path: inset(0)` —— 前の上をせり上がって覆う |
| セクション | **`overflow-x: clip`**（`hidden` ではない。hidden だと sticky が死ぬ） |
| JavaScript | **一切なし。**scroll駆動アニメーションのCSSも0件 |

**MIXでの調整** —— カードをビューポート丸ごとの高さにしない。
参考サイトのカードは画像＋本文＋導線で埋まっているが、こちらは1行＋1文なので白が余る。
実測で `min(42svh, 268px)`。カード間の隙間は0（空けると「覆う」動きが途切れる）。

### 旧実装（横スライド・2026-09-08 に置き換え）

- 横移動は **CSS の `scroll-snap-type: x mandatory`**。モバイルのスワイプは素の挙動。
- **JSは現在位置の表示と矢印だけ**（`js/slider.js`）。JSが死んでも3枚とも横スクロールで読める。
- 矢印は**JSが動くときだけ出す**（押しても何も起きないボタンを見せない）。
- 現在位置は**点**（画面）と **`1 / 3`**（読み上げ用・`aria-live`）。
- 実測: 次のカードの端が **62px** 見える。

## MIXへの翻訳（当初案・不採用）

イベント概要は、1つの長い説明文にせず、3枚のストーリーカードに分ける。カードの順番は固定する。

| 番号 | カードの役割 | 表示する事実 |
| --- | --- | --- |
| 01 | WHAT IS MIX | ASOBIBARで行う恋愛リアリティ体験 |
| 02 | CHIME | チャイムが鳴ると、そこからお題が出される |
| 03 | CROSS | 最大4〜6組のグループが交差する |

各カードは次の順で読む。

1. 小さな番号または英字ラベル
2. 日本語の見出し
3. 1〜2文の説明
4. 必要な場合だけ、事実を短く強調する行
5. 次のカードへ進むためのインジケーター

概要セクション内に予約ボタンを置かない。CVはページ末尾の公式LINE導線へ一つに集約する。

## 後でコード化するときの動き

以下は、参考サイトのカード切り替えの考え方をMIX用に具体化した実装仕様である。

- 1枚分のカードを横方向のトラックとして持ち、現在カードが切り替わると画像・見出し・本文を同じ番号で同期させる。
- デスクトップは左右の矢印とホイール操作、モバイルは横スワイプで1枚ずつ進む。カードを途中で止めず、次のカードの端を少し見せて続きがあることを伝える。
- 切り替えは、現在カードが少し横へ抜け、次のカードが同じ方向から入る。背景面は残し、カード内の文字と画像だけを入れ替える。
- 自動再生はしない。読んでいる途中に勝手に内容が変わらないことを優先する。
- 切り替え時間は実装時に調整するが、初期値は600〜800msの滑らかなイージングとする。移動量はカード幅を基準にし、カードごとに異なる飛び方をさせない。
- `prefers-reduced-motion: reduce` では横移動とフェードを短くするか無効にし、カードの内容と順番は同じにする。
- キーボード操作と現在位置の表示を用意し、現在のカードが読み上げで分かるようにする。

## カンプで先に確認すること

- 3枚のカードを同じフレームへ入れたとき、イベントの概要が先に理解できるか。
- 次のカードの端が見える量が、装飾ではなく「続きがある」手がかりになっているか。
- 人のシルエットまたは写真が本文の可読域を邪魔していないか。
- 「恋愛リアリティ体験」「チャイム」「最大4〜6組」の3点が、1枚に詰め込まれず順番に残るか。
- 背景の紫〜ピンクのランプと、白またはスモーキーピンクの読ませる面の役割が崩れていないか。

この段階では、カードの見た目と情報の順番だけを決める。HTML・Sass・JavaScriptの編集は、デザイン確認が終わってから行う。
