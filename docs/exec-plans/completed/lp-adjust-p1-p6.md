**追加対応（1280px超の紫の帯）**

- **症状。**`.page` を `max-width: 1280px` で中央に置いていたため、それより広い画面では
  外側に `body` の地色 `--ramp-01`（`#24102e`）が帯で出ていた。
  **1440で左右80pxずつ、1920で左右320pxずつ。**依頼者の指摘（2026-09-09）。
- **意図ではなかった。**1280pxのコンテナは意図的（`pc-grammar-comes-from-futuretrain`）だが、
  **その外側をどう見せるかは決めた記録が無く**、body の既定色が素通しで出ていただけ。
  参考にした futuretrain は「コンテナ1280 / 1440フルブリード」で、背景は全幅に走らせていた。
- **直し方。**PC節で `.page` の上限を外し（`max-width: none`）、節の左右余白を
  `--pc-edge: max(--pc-gutter, (100% - --pc-content) / 2)` に替えた
  （`--pc-content` = 1280 − 80×2 = 1120px）。
  **背景だけ全幅に走り、中身の列は 1120px のまま。**
- **1280px以下は1pxも変わらない。**その幅では `max()` が常に 80px を選ぶので、
  以前の `padding: 120px 80px` と完全に同じ値になる。1280pxの前後で段差も出ない。
- 同じ置き換えを `.site-header` / `.footer` / `.mechanism` / `.hero` の左右余白にも適用した
  （中身の列を揃えるため）。**`.hero__keyart` の `margin-inline: calc(--pc-gutter * -1)` は
  変えていない** —— 1120pxの列から左右80pxはみ出して、バナーはコンテナ1280の端で止まる。
  ここを `--pc-edge` にすると画面端まで伸び、1920px超で支給素材（1920x1080）を
  原寸より拡大してしまう（AGENTS.md で禁止）。
- **装飾は画面の端へ移った。**`.intro__pair`（乾杯SVG）、`.outline-word`、`.chime__ring` などは
  節に対する絶対配置なので、全幅化で本当の画面端へ寄る。
  `sound-trip-composition-frames-the-page` ③「中央を可読域として空け、装飾は左右端・四隅へ寄せる」
  の方向と一致するので、そのままにした。

**踏んで直した罠（記録済み）**

- `sips --cropOffset` は**中央基準**。左端0のつもりが中央が出て、1枚目と2枚目が
  ほぼ同じ絵になった。以後、切り出しは PIL で座標指定する。
- `<picture>` を挟むと**グリッドの子は img ではなく picture** になる。配置と高さは
  picture へ効かせる。
- グリッドの行を暗黙の auto のままにすると子の `height:100%` が auto に落ち、
  写真が本来の比で伸びてカードから **1920pxで97pxはみ出していた**。1440pxでは
  たまたま高さが一致していて気づけなかった。`grid-template-rows: minmax(0, 1fr)` を明示。
