# ディレクトリ名に濁点があると、git の返すパスと `pwd` が文字列として一致しない

- **踏んだ日:** 2026-09-07

## 症状

`sh scripts/install-hooks.sh` が、リポジトリのルートとプロジェクトが同じ場所なのに
「ここはリポジトリの一部でしかない」という注意を出した。

```
NOTE: the git repo is /Users/rintaro/Job/LP/MIX交流上等バンドLP, and this project is only
      /Users/rintaro/Job/LP/MIX交流上等バンドLP inside it.
```

**同じパスが2回出ている。**`${PROJECT_ROOT#"$REPO_ROOT"/}` で前方一致を削るはずが、
削れていない。

## 原因

**「バ」の表現が違う。**

| 出どころ | バイト列 | 正規化 |
| --- | --- | --- |
| `pwd` | `e3 83 90` | NFC（U+30D0 バ） |
| `git rev-parse --show-toplevel` | `e3 83 8f e3 82 99` | NFD（U+30CF ハ + U+3099 濁点） |

同じディレクトリを指しているが、**文字列としては一致しない。**macOS のファイルシステムは
正規化の違いを同じ名前として扱うので、`cd` も `open` も普通に通る。**比較だけが落ちる。**
`ASOBIBAR` や `Y2K` のようなASCIIの名前では起きない。**濁点・半濁点を含む日本語の
ディレクトリ名で初めて出る。**

## 影響していないこと（確認済み）

- **ハーネスの検査範囲は正しい。** `harness-check.mjs` は `files=33` を返し、
  `scope=` の行を出さない（= prefix が空 = リポジトリ全体 = このプロジェクト）。
  ここが壊れると **「差分なし・全部pass」という顔で何も見ないまま通る**ので、
  骨組みを入れたときに実測した
- `core.hooksPath` は絶対パスで正しく入っている。hook は動く

## 直したもの

**何も直していない。**出力の文面だけの問題で、動作は正しい。
`scripts/install-hooks.sh` は**共有元にある実体**で、直すと参照している全プロジェクトに
効く。文面のために共有ファイルを触る価値は無いと判断した。

## 次から

**パスを文字列で比較するコードを、日本語名のディレクトリの下で信用しない。**
比較が要るなら、両方を同じ正規化に寄せる（`git -c core.precomposeunicode=true`、
あるいは `python3 -c "import unicodedata;..."`）か、**inode で比較する**
（`[ "$(stat -f %i "$a")" = "$(stat -f %i "$b")" ]`）。

**ハーネスに新しい「パスの前方一致」を書くときは、このプロジェクトで実測すること。**
検査範囲の計算を間違えると、落ちるのではなく**通ってしまう。**
