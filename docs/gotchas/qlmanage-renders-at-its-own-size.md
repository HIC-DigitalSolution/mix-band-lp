# qlmanage は自分の都合の幅と高さで描く

- **Date:** 2026-09-09
- **出どころ:** `tools/render.sh` でPC幅の確認をしようとして2回続けて騙された
- **関連:** `harness/contracts/mix-lp.yaml` の `output-is-rendered-and-seen`

`tools/render.sh` の描画経路は qlmanage（QuickLook / WebKit）。**`-s` は出力画像の
幅であって、ページのビューポート幅ではない。**そして出力の高さには上限がある。

## 1. メディアクエリが `-s` の幅で評価されない

PC用の `@media (min-width: 900px)` を入れた直後、375px指定で出したはずの確認画像が
**全部PCレイアウトだった。**qlmanage は自前の広い幅で描画してから縮小するので、
`-s 375` は「PCで描いた絵を375pxに縮めたもの」になる。縮んでいるだけなので
一見それらしく、**気づかないまま「SPを確認した」と言える。**

対策: 第4引数 `VIEW_W` を渡すと、その幅の iframe に入れてから描く。

## 2. 高さが約1400pxで黙って切れる

5,565px のPCページを `VIEW_H=5600` の iframe で1枚に出したら、**FVしか写らず、
6分割した6枚が全部FVの中だった。**エラーは出ない。切れた分は無音で消える。

対策: 第5引数 `VIEW_H` を画面1枚分（例 1000）にして、第6引数 `OFFSET` を
送りながら帯で見る。

```sh
for o in 0 1000 2000 3000 4000 5000; do
  ./tools/render.sh index.html 1300 1 1440 1000 $o && cp tmp/render/index.png tmp/render/pc-$o.png
done
```

## 教訓

**描画したことと、見たいものが写っていることは別。**出た画像の中に、
確認したかった要素が実際に写っているかを毎回確かめる。写っていなければ、
それは「確認していない」であって「問題なし」ではない。
